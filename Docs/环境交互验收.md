# 环境与入口交互

当前修复范围为 2026-10-18 住宅演示录像中的时间、夜景和入户玻璃门交互问题。

| 问题 | 原因 | 当前行为 |
|---|---|---|
| 正午启动演练后变夜晚 | 火警入口调用恢复原夜景 | 保留已选时刻，启动和重置均不更改时钟 |
| 手动夜间比默认夜景暗 | 日照预览强制覆盖曝光、移除了原夜景补光及天空 | 夜间回到同一夜景标定，日间保留独立太阳和天空计算 |
| 天黑后起夜灯未启动 | 录像末段为 18:10；太阳已落山，旧规则仍要求晚于 19:00 | 判断模拟太阳高度，低于 6°时允许引导照明；状态说明与控制共用判断 |
| 入户门只能瞄准边框 | 可见性射线穿过无碰撞三角面的玻璃 | 对实际窗扇局部包围盒补充射线判定，选择最近的门，保留遮挡与 2.3 米限制 |
| 夜间切回正午后演练出现灯光重建红字 | 新大气启用早于渲染场景移除旧静态天空，留下错误的静态依赖 | 统一首次和再次进入白天的启用顺序，待旧天空移除后启用大气 |

火警运行时，时间预设、滑块、恢复夜景和观察点均不可切换，防止演练状态被其他页面操作打断。能源对比仍只恢复照明配置，进入起夜场景不会修改日照时间。

## 可重复检查

在编译、打包后的候选程序目录执行：

```powershell
.\Tools\check_environment_regression.ps1 -GameRoot "候选程序的Windows目录"
.\Tools\check_daylight.ps1 -GameRoot "候选程序的Windows目录" -EvidenceRoot "验收记录目录\Daylight"
.\Tools\check_smart_lighting.ps1 -GameRoot "候选程序的Windows目录" -EvidenceRoot "验收记录目录\SmartLighting" -Heights 720
.\Tools\check_daylight_smoothing.ps1 -GameRoot "候选程序的Windows目录" -EvidenceRoot "验收记录目录\Smoothing"
```

环境检查覆盖正午火警、重置、手动 21:00、18:10 起夜、白天暂停/夜间恢复、实际面板按钮、玻璃九点识别、遮挡和 E 开关。它使用固定测试位置，不代表连续步行验收；截图需要单独检查，灯具强度非零不等于画面可见。

本机完整证据位于 `D:\HouseCoursework_Team\Saved\Acceptance\EnvironmentFix`，不上传大型截图、日志或私人资源。源码与资源分开管理，本轮未修改 Content，不需要新的资源增量包。发布入口继续为 `D:\HouseCoursework_Build\Windows\HouseCoursework.exe`。
