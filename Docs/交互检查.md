# 交互一致性检查

2026年10月25日，基于v0.20.0检查门、窗、灯和家电的识别与操作。修改前源码标记为 `交互打磨前-20261025`。

## 本轮修正

1. 将灯具原有的双向不透明遮挡检查提取为共用逻辑，并接入家具、窗户和家电的目标识别。单面薄墙从背面可能不响应普通射线；现在也从目标向观察者反查，避免隔着不透明物体出现E提示和触发操作。透明材质沿用原有处理，目标自身及端点附近接触不会作为额外遮挡。
2. 火警演练中，家电电源仍保持锁定；对家电按E时显示与窗户相同的“演练期间请优先疏散”，解释操作为何没有执行。门保持正常开关，方便撤离。

没有调整交互距离、按键、灯光存档、天气、能源算法或控制面板布局。只使用原有资源，不增加网盘素材包。

## 如何验证

```powershell
.\Tools\check_clock_foundation.ps1 -Mode interaction -Height 1080
.\Tools\check_clock_foundation.ps1 -Mode interaction -Height 720
.\Tools\check_clock_foundation.ps1 -Mode fixture -Height 1080
.\Tools\check_clock_foundation.ps1 -Mode ventilation -Height 1080
.\Tools\check_clock_foundation.ps1 -Mode household_weather -Height 1080
.\Tools\check_clock_foundation.ps1 -Mode drill_restore -Height 1080
```

interaction检查电脑和两台电视在正常站立高度下的识别、提示动作、E开关、连续按键、超出距离、实体障碍、单面薄片背面、面板中的E输入以及火警结束后的恢复。控制器输入按游戏下一帧处理，涉及E的结果在后续帧检查，防止把尚未执行的输入误判为已被阻止。

修改前专项运行中，三个家电均在单面薄片背面被选中；日志 `INTERACTION_THIN_FORWARD blocked=0` 记录普通正向射线漏检，随后出现家电电源切换日志。修改后对应目标识别和阻止操作检查均应通过。

fixture逐个检查已登记灯具的可达性、开关、调光、实际光源和发光材质，以及提示反馈。ventilation覆盖16个活动窗扇；家具检查使用现有furniture模式，每个登记部件完成两轮E打开、关闭，并检查可见性、关闭位置和附着装饰的归位。

证据目录为维护机的 `Saved/Acceptance/InteractionPolish`，其中Before保留修正前专项记录。灯具画面与库存编号必须使用同次运行的清单对照。离屏验收不作为正常游戏帧率证明，本轮也不重复认证全天气候模拟。

## 连续路线与性能证据

`Tools/check_walkthrough_audit.ps1`为连续路线提供中午、雨天、就寝起夜和火警四种明确条件。每次先等待环境和天气稳定15秒，随后通过真实CharacterMovement与E输入经过47个路线点，不在途中传送或关闭人物碰撞。火警条件还须在日志中出现真实报警与住户集合记录。

```powershell
# 默认后台运行，只验功能、碰撞和截图，不认证前台帧率。
.\Tools\check_walkthrough_audit.ps1 -CaptureScreenshots

# 正式性能运行时需保持住宅窗口前台，不操作其他窗口；不得同时截图。
.\Tools\check_walkthrough_audit.ps1 -Foreground
```

报告记录实际渲染分辨率、预热时间、逐帧耗时、GPU耗时和Windows实际前台状态。`scenario_valid`同时核对时刻、模式及天气或警情；起夜测试必须保持自动模式，不能由测试初始化误设成全屋手动接管。只有全程前台、关闭截图、非离屏渲染且采样充分时，`benchmark_eligible`才为true；后台报告的`performance_passed`为null，不能把其平均帧率作为评分要求的证明。正式性能检查还要求平均不低于25 FPS；长帧与首次操作卡顿需继续单独检查。

旧route模式保留用于历史复现，默认沿用原夜景。不能只看文件名中的route或命令行请求的分辨率，就认定测过当前中午或雨天的正常窗口性能。验收位置仍由程序控制，不能代替人工鼠标观察所有物件。
