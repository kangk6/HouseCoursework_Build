# 雨天室内采光修正

2026年10月26日，修复v0.21.0在白天切雨天后室内比夜间更暗的问题。

## 原因与处理

同一盏灯的实际输出没有变化，但白天环境后处理把曝光最小值和最大值都设为1，夜间原场景则允许0.15–5的曝光适应。雨天直射光下降后，白天画面仍被锁定；夜间反而能适应暗处，导致九个固定房间视角都出现反向明暗关系。

白天现在读取原场景全局后处理的曝光范围、补偿与测光方式，保持昼夜同一套规则，不按“雨天”额外调高曝光偏移。关于相等最小／最大值会禁用曝光适应，见[Epic曝光文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/auto-exposure-in-unreal-engine?application_version=5.3)。

同时，天空光使用既有天气散射系数，取消按云量再次压低环境光的处理。原有客厅与主卧的两处微弱环境反弹光不再白天归零，白天按散射系数的0.8倍缩放，夜间保持原强度。0.8是现有场景的视觉校准系数，不代表真实光学参数；白天已有天空光，辅助反弹光只补剩余部分。没有新增灯具、修改用户灯光设置或改变灯具用电。

上述室内修正未调整太阳直射、光伏辐照度、降雨强度和智慧照明规则。曝光调整只作用于最终画面，不乘进电量；夜间实际灯光配置也保持原样。后续室外渲染校准见下节。

## 验证

```powershell
.\Tools\check_clock_foundation.ps1 -Mode rain_brightness -Height 720
.\Tools\check_clock_foundation.ps1 -Mode rain_brightness -Height 1080
```

每次使用相同房间位置和视角、相同灯光开关与亮度、关闭家电屏幕，依次采集晴天中午、雨天中午、雨天午夜。九个房间共27幅画面，每幅等待3秒后采样中央偏下的室内区域，记录0–255亮度均值、近黑与近白像素比例。

验收要求：九个指定视角的雨天中午不能明显暗于同配置雨夜，仍比晴天有阴雨层次，室内不能大面积压黑或泛白。37项检查包含有效像素与每房间四项条件；这不是对所有位置、灯光组合或真实照度的证明。截图需人工核对，不能只看灯光Intensity数值。

另回归雨天效果、家电天气、光伏、智慧照明联动、火警恢复，并自然运行完整昼夜循环检查晨昏与午夜画面亮度变化。维护机证据目录：`Saved/Acceptance/RainIndoorLighting`。Before为修正前对照，Trial为统一曝光后的中间对照，Final为最终验收；不要混用不同程序的记录。

## 室外天空与阴影

2026年10月28日补充修正院子逆光视角。云层材质的白天总色倍率原为1，而它是自发光天空，并非普通表面颜色；加上夜景沿用的2.12光晕强度和约0.029的低门槛，阴雨天空与树叶边缘容易泛白。现在云层总色倍率为0.06，云层颜色收敛到中性灰，天气切换使用已有连续云量插值。镜头光效随后扩展为下面的昼夜统一设置，避免仅在雨天减轻、晴天或夜间又出现灯具耀斑。

阴雨直射光按原天气强度的0.4倍显示，捕获天空光按原散射强度的3倍校准，让光照更多来自天空。完整保留墙体遮光，不使用降低阴影遮挡率的方式给室内补光。上述数字是这套素材与曝光下的渲染校准，不是真实照度或云层辐照度；光伏、用电与智慧照明的天气计算没有改动。太阳源角增大，但现有级联阴影仍不等于真实云层软阴影。

新增固定室外检查：六个院子、车道和屋顶方向，分别采集晴天中午、阴天中午、雨天中午与雨天午夜，共24幅原生画面。上部区域记录近白像素占比，下部区域记录亮度。上部包含建筑和树木，不能当作精确天空分割；统计通过后仍需查看图片，并回归九个室内视角。

## 灯具近距离眩光

原场景的Lens Flare会把灯罩等高亮区域变成画面另一侧的绿色、紫色或黄色光斑。运行时使用独立的全局后处理层：镜头耀斑强度为0，Bloom强度为0.45、门槛为1，保留少量高亮柔光。该层与昼夜曝光的混合权重分开，晴天、阴雨和夜间使用一致规则，随后加入下述中性白平衡。它不修改灯具Intensity、发光材质、曝光范围或能源功率；环境恢复时销毁该层，原场景资源不改写。

`lamp_glare`检查六个近距离灯具视角，分别采集晴天中午、雨天中午和午夜，共18幅图，记录后处理设置、亮度与近白像素比例。仍须查看图片确认彩色光斑与灯罩边缘表现，不能只凭参数判断。

```powershell
.\Tools\check_clock_foundation.ps1 -Mode lamp_glare -Height 1080
```

## 室内色温校准

原夜景后处理的白平衡约4757K，SceneColorTint的红通道为0.927；该全局调色也作用于白天。部分受控室内补光同时使用约7187K至11804K的冷色温，导致白色门框、墙面和人物整体偏蓝。运行时将白平衡设为6500K、Tint设为0、SceneColorTint设为白色，保持昼夜一致；自然天空仍可呈冷色，灯具仍可呈暖色，不使用全画面橙色滤镜。

仅将受控室内灯中启用色温且高于6500K的分量改为4000K，厨房与书房为4500K。已有低色温灯具保留。两盏既有环境补光从(0.5,0.6,0.8)收敛到(0.58,0.6,0.64)，线性亮度接近原值，减少蓝色染色。灯具数量、强度、衰减半径、开关调光与能源额定功率不变，智慧场景退出后仍恢复校准后的灯色。

九房间三场景检查新增中性调色、室内色温和未构建光照检查，输出`InteriorLightingSources.json`记录受控灯实际色温和强度，并采集27张原生画面。首次机位至少预热12秒，每个机位至少等待24帧及3秒，避免低后台帧率时把曝光尚未稳定的画面作为对照；检查阈值不放宽。截图对照仅证明指定机位的视觉变化，不代表真实照度或每一位置的色彩测量。还需回归近距离灯具、室外天空、智慧照明、能源、火警恢复与昼夜连续性。维护机证据目录为`Saved/Acceptance/InteriorLighting`。

源码回滚标签为`室内光感校准前-20261028`，运行版快照为`D:\HouseCoursework_Build\Rollback\before-interior-lighting-20261028`。原始关卡及材质不改写，资源包无需更新。

低后台帧率还暴露了天空初始化的时序问题：原来的0.1秒定时器可能在移除旧静态天空光的同一帧触发，令新大气记录错误的静态构建依赖。现在先跨过激活帧，再用异步渲染栅栏确认旧天空光更新已处理，才启用新大气，不阻塞渲染线程，也不屏蔽构建警告。九房间采样会检查未构建对象计数。
